# HUD 会话行的排列规则（2026-11-06）

> 外观（黑色变形胶囊、状态灯、行样式）见 [hud-style.md](hud-style.md)；本文只讲哪些会话占行。

## 问题

浮窗为每一个已知的会话各留一行。会话只要被扫描到（最长 24 小时内），就算已经看过、没有任何事发生，
也会留下一行灰色图标；常驻显示模式下这些灰行永远在，所以浮窗只增不减。Antigravity 与 Claude Code 都是如此。

## 规则

一个会话**只有在有东西可看时才占一行**：

| 状态 | 是否占行 |
| --- | --- |
| 需操作、执行中、失败、已中断 | 占行 |
| 已完成且尚未查看 | 占行，点「已查看／待命」后**整行消失** |
| 已完成且已查看、空闲、未知 | **不占行**，折回该助手唯一的图标 |

按有多少会话需要注意：

- **0 个**：该助手只显示一个图标（常驻模式下为灰色，「活动时显示」模式下整个隐藏）。
- **1 个**：Claude 仍用原来的助手行；Antigravity 用该会话自己的行，但名称为「Antigravity」而不是「会话 N」。
  Antigravity 不折回助手行，是因为它的回覆绑定在具体会话上（逐会话的提前验证、问题身份、已验证的问题），
  改走助手级路径会绕过这些。
- **2 到 3 个**：每个会话一行，名称「Antigravity · 会话 N」／「Claude · 会话 N」，沿用稳定的编号。
- **超过 3 个**：最需要使用者的 3 个保留自己的行，其余折成一个「+N」标记。标记的颜色取被藏起来的会话中**最糟的状态**，
  所以需要操作的会话不会被埋在里面。点击「+N」弹出清单，列出被折叠的会话；完成的可直接点「已查看」，
  需操作的可「打开处理」跳到原窗口；Claude 的单个单选问题在装了 Hook 后改为「回答」，直接在岛上选。

保留哪些行按紧迫度挑选（需操作 > 执行中 > 已完成 > 失败 > 已中断，同级按稳定顺序），
但显示时仍按稳定顺序排列，行不会因状态变化而跳位。上限为 `AppState.maximumRowsPerProvider = 3`。

## Codex（2026-11-08 起）

Codex 以前不论开几个会话窗都只有一行（取最新的那个），第二个会话窗在后台完成了，灵动岛上看不出来。
现在与 Claude 一样按会话占行，规则相同（「一个会话只有在有东西可看时才占一行」、1 个沿用助手行、2–3 个各一行、超过 3 个折成「+N」）。
差别在这几处：

- **会话从哪来**：需要回答的请求 > Codex 桌面应用对它已打开的会话的回答 > 本地记录（执行中，或已完成并带完成时间）。
  桌面应用只回答它自己打开着的会话，所以另外两个来源必须并进来，否则没被它回答的会话就看不见。
- **已完成的会话何时算已查看**：自己的标记盖得住完成时间，**或者**助手级的标记盖得住。后者是会话有自己的行之前唯一的记录，
  没有它，今天早些时候完成、早已看过的会话都会一下子冒出来。逐会话的标记会保存，重启后仍在。
- **编号**：只给「有东西可看」的会话编号，看过之后把号码还回去，新来的取最小的空号。24 小时内看过的会话不占号，
  所以屏幕上是「会话 1」「会话 2」，不是「会话 5」「会话 6」。
- **打开**：点一行最前面的 logo，用 `codex://threads/<会话 id>` 直接打开那个线程，并且只把这个会话标为已查看。
  助手行（只有一个会话需要注意时）也一样：恰好只有一个可打开时就打开它。程序自己把 Codex 提到前台引起的那次「应用被激活」，
  6 秒内不当作「用户切换过去看了全部」。
- **局限**：用户**自己**切到 Codex 应用时，仍然算作看过所有已完成的会话。Codex 没有对外给出「屏幕上是哪个线程」的信息，
  这里无从区分。Claude 桌面应用有（见下），所以那边只算正在看的那一个。

## Claude 桌面应用：只有屏幕上的会话算「看过」

Claude 桌面应用在每个会话的文件里记录 `lastFocusedAt`（最近一次聚焦）。应用在最前面时，聚焦时间最新的那个就是屏幕上的会话。
所以另一个会话在它后面完成，不再因为「应用在前面」而被当成看过；只有正在看的那个才算。读不到这条记录时，退回「它托管的所有已完成会话都算」。
终端、编辑器没有这条记录，规则不变。

## 为什么不用「母／子目录」

浮窗是扫一眼的东西，展开层级多一次点击，对一个小药丸太重。完整、有层级的清单更适合放在菜单栏面板里；
浮窗只放要注意的。目前「+N」点开的清单就是这个折衷。

## 实作

`AppState.arrangeSessionRows` 是两个助手共用的单一挑选逻辑；`claudeArrangement` 与 `antigravityArrangement`
负责把各自的会话转成行（已查看的先标为空闲）。`expandClaudeSessions`／`expandAntigravitySessions` 保持原签名。
`AppState.hiddenSessionRows(for:)` 提供「+N」清单的内容。`SessionRowArrangementTests` 覆盖以上规则。

## 真实资料验证

对真实会话与隔离版偏好里真实的「已查看」记录：Antigravity 两个已看过的会话，旧逻辑 2 行，新逻辑 1 行。
Claude 的两个会话一个执行中、一个刚完成未查看，仍是 2 行（都需要注意）。

## 尚未验证

- 画面效果未经目视（没有萤幕录製权限）。「+N」标记与点开的清单是新的视图，需要实机确认外观与点击行为，
  尤其是在非激活的浮动面板上弹出 popover 是否正常。
- 超过 3 个会话的情形只有单元测试，本机没有这么多同时活动的会话可供实测。
- Claude 的「已查看」只存在记忆体，不跨重启保存（Antigravity 的会保存）。重启后已完成的 Claude 会话会再出现一次。
